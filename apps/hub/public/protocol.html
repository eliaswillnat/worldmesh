WorldMesh protocol

An open foundation for the connected 3D web.

The goal is simple: websites can remain independent while sharing optional conventions for movement, discovery, portals and characters. No single city should need to own every destination.

Available building blocks

  • Independent worlds: developers host their own code, content and infrastructure. Worlds can be listed by URL.
  • Shared controls: @worldmesh/runtime provides navigation, player controls and portal links for Three.js worlds.
  • World manifests: optional worldmesh.json metadata helps directories identify a world's name and properties.
  • Presence: compatible worlds can use the optional hosted multiplayer presence relay, or operate their own relay.
  • Avatar wallet: users can connect supported character providers. WorldMesh saves references, not character model files, and compatible worlds can receive a selected character via a limited handoff ticket.

Doorway: the transition specification

Doorway is a draft open specification for looking through and walking into a different 3D website. The current hub and runtime implement parts of its live-view and crossing flow; support varies between destinations. Ordinary links remain the fallback. Seamless travel is not guaranteed for every world or browser.

Planned: interoperable cities

The next step is to specify how independent discovery cities can recognize one another and serve their own directories while users keep the same portable identity and character. This is not yet a finished or deployed city federation standard.

Shared identity across separately operated cities needs a secure sign-in and authorization design, not merely an avatar handoff URL. Existing AT Protocol or OpenID Connect standards may help; the choice and trust boundaries still need validation.

Design principles

  • No requirement to host a world or city with WorldMesh.
  • Open specifications and independent implementations, rather than one mandatory operator.
  • Explicit user consent and scoped access when sharing identity or characters.
  • Graceful fallback when a destination does not support advanced transitions.
